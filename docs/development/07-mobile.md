# Mobile (Android)

`apps/mobile` is the Android app, written in **React Native + Expo** (TypeScript). Its main
screen is the Jarvis assistant; a side menu leads to quick logs (water). It talks to the
**same API** as the website (`<server>/api`) with the **same session cookie**.

## Not an npm workspace

`apps/mobile` has its own `package.json` and `package-lock.json` and is installed from
inside its folder. The root workspaces are only `packages/*`, `apps/backend` and
`apps/frontend`, so the server's `npm ci` never downloads React Native.

```bash
cd apps/mobile
npm ci
```

## Structure

```
apps/mobile/
├── app.config.ts          name, package, version, permissions, plugins
├── plugins/               config plugins: LAN http, ABIs, release signing
├── scripts/
│   ├── build-apk.mjs      expo prebuild + Gradle → build/apk/MyHomeLab-<version>.apk
│   └── generate-assets.mjs
├── assets/
└── src/
    ├── App.tsx            providers + navigation
    ├── api/               fetch client, endpoints, types
    ├── context/           Auth, Menu, Update
    ├── navigation/        native-stack + side menu
    ├── screens/           login, assistant, quick log
    ├── hooks/ components/ theme/ utils/
    └── i18n/              pt-PT, en, es (same keys in all three)
```

The `android/` folder is generated by `expo prebuild` and is not committed (nor are
`build/`, the keystore, or APKs).

## Networking and session

- Requests go to `<server>/api<route>` with `credentials: 'include'`; the cookie is kept by
  Android's native cookie store across restarts.
- A 401 (outside login) ends the session; a network error with a stored session lets the
  user in with the cached user.
- Routes used: `/auth/login`, `/auth/me`, `/auth/logout`, `/assistant/history`,
  `/assistant/chat`, `DELETE /assistant/history`, `/health/water`, and `/app/android`.
- Plain `http://` is allowed so the app can reach a server on the LAN.

## New-version banner

On start the app calls `GET /app/android`. If the server reports a newer version with a
download URL, a banner offers to download the APK.

## Versioning

The app's version **is the server's version**: `app.config.ts` reads `APP_VERSION` (passed
by the build script) or the latest `vX.Y.Z` git tag. The Android `versionCode` is
`major * 10000 + minor * 100 + patch`.

## Develop

```bash
cd apps/mobile
npx expo run:android      # development build on an emulator or USB device
npx expo start            # then just Metro
npm run typecheck
```

On the emulator, the host machine is `http://10.0.2.2:<port>`.

## Build an APK

Needs the Android SDK (`ANDROID_HOME`). On Windows, install CMake 3.31.6
(`sdkmanager "cmake;3.31.6"`): older CMake rejects the long paths React Native generates.

```bash
cd apps/mobile
node scripts/build-apk.mjs 1.2.0                # release APK (arm64-v8a + armeabi-v7a)
ABIS=x86_64 node scripts/build-apk.mjs 1.2.0    # for the emulator
```

Output: `apps/mobile/build/apk/MyHomeLab-<version>.apk`.

### Signing

Release APKs are signed with a keystore configured in `apps/mobile/keystore.properties`
(`storeFile` relative to `apps/mobile`, `storePassword`, `keyAlias`, `keyPassword`). Both
the keystore and the properties file are **outside git — keep a backup**: if the key is
lost, new versions can no longer install over the old app. Without `keystore.properties`
the release build falls back to the debug signature.

## Publishing with a release

`scripts/android-release.mjs` builds the APK and attaches it to the **GitHub Release** of
the tag as `MyHomeLab-X.Y.Z.apk`:

- `npm run release -- --push` runs it automatically after pushing the tag. It waits for the
  Release workflow to create the GitHub Release, then uploads (replacing an existing asset
  with the same name).
- Run it alone to (re)publish an existing tag:

  ```bash
  npm run release:android                  # tag on HEAD (or the latest)
  npm run release:android -- v1.2.0        # a given tag
  npm run release:android -- --build-only  # build only
  ```

- Publishing needs a GitHub token with `contents: write` in `GITHUB_TOKEN` / `GH_TOKEN`, or
  the GitHub CLI signed in (`gh auth login`). Without a token the APK is built but not
  published. If the APK step fails, the tag is not undone — just re-run the command.

The server's `GET /app/android/download` redirects to the APK of its installed version,
which gives a stable download link.
